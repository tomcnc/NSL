## 0. Introduction

This project aims to address the **Traveling Salesman Problem (TSP)**, a classic problem in discrete combinatorial optimization. Due to the discrete nature of the domain and the complexity of the cost function landscape, standard gradient-based optimization techniques are inapplicable.

The TSP represents a class of **derivative-free optimization** problems. The optimization process relies on direct evaluations of a cost function characterized by numerous local minima, making the search for a global optimum computationally non-trivial. In the field of complexity theory, the TSP is classified as **NP-Hard**.

### Problem Statement
Consider a set of $N$ cities arranged on a 2D plane, identified by indices (labels) $x_i \in \{ 1, 2, \ldots, N\}$. The objective is to determine the optimal sequence of indices that minimizes the total distance traveled (or the square of the distance), subject to two fundamental constraints:
1.  Each city must be visited exactly once.
2.  The path must be a closed loop (the final city must connect back to the starting city).

The loss function is defined as:

$$L^{(1)}(X) = \sum_{i=1}^{N} |\vec{x}_i - \vec{x}_{i+1}| \quad \text{or} \quad L^{(2)}(X) = \sum_{i=1}^{N} |\vec{x}_i - \vec{x}_{i+1}|^2$$

Periodic Boundary Conditions (PBCs) are applied such that $x_{N+1} = x_1$, ensuring the return to the starting point.

### Methodology: Genetic Algorithm
This problem is approached using a **Genetic Algorithm (GA)**, a metaheuristic algorithm inspired by the process of biological evolution. Like other metaheuristics, GAs balance **intensification** (exploiting good solutions) and **diversification** (exploring the parameter space). The algorithm generates a population of candidate solutions and evolves them independently. Following the principle of natural selection, individuals that adapt best to the environment (i.e., minimize the loss function) have a higher probability of surviving and reproducing, while less fit individuals are destined for extinction.

Evolution is driven by three primary operators acting on the population:
1.  **Selection Operators:** Individuals exhibiting higher fitness (lower cost) are statistically selected with higher probability for reproduction.
2.  **Crossover Operators:** Selected parents exchange genetic material to generate offspring. This process aims to combine advantageous genetic sequences from both parents to produce superior solutions.
3.  **Mutation Operators:** Random alterations are introduced to an individual's genetic sequence. This introduces variability into the population, preventing premature convergence to local minima, though it risks disrupting optimal traits.

## 2. Configuration File Structure

### `input.dat`: Simulation Parameters

This file contains configuration parameters necessary to set up the simulation.

| Parameter | Recommended Value | Description/Notes |
| :--- | :--- | :--- |
| `RND_ROW` | $0$ | $0$: `Primes` file row read to set the LCG seed. |
| `N_PATH` | $1000$ | Total number of paths (chromosomes) composing the population. |
| `N_ELITE` | $100$ | Number of best paths preserved for the next generation (Elitism) without undergoing crossover or mutation. |
| `N_CITY` | $34$ | Total number of cities composing a single path. |
| `CITY_DISTRIBUTION` | CIRCLE/SQUARE | Geometric distribution of cities in the plane. |
| `P_SWAP` | *0.10* | Probability of **Swap Mutation**: $L$ contiguous cities are swapped with other non-overlapping $L$ contiguous cities. |
| `P_SHIFT` | *0.10* | Probability of **Shift Mutation**: $L$ contiguous cities are shifted (left or right) by a random step size. |
| `P_CROSSOVER` | *0.80* | Probability of **Crossover**: High-fitness paths are selected to mix genes and create two new individuals. |
| `P_INVERSION` | *0.10* | Probability of **Inversion Mutation**: The order of $L$ contiguous cities is inverted. |
| `ENDINPUT` | N/A | Marker indicating the end of the input file. |

### `properties.dat`: Measurable Properties

This file lists the properties the simulator measures and outputs.

| Parameter | Description | Implemented |
| :--- | :--- | :--- |
| `BEST_LOSS` | Measure and prints the loss function associated with the best path of the population | ✅ |
| `MEAN_LOSS` | Measure and prints the average loss function associated of the best half path of the population | ✅ |
| `BEST_PATH` | Prints the best path sequence of each generation based on the lowest loss function. | ✅ |
| `ENDPROPERTIES` |  Marker indicating the end of the properties file. | - |

### `circle_map.dat` and `squared_map.dat`

These files contain the city distributions described by cities labels (first column), x-coordinate (second column) and y-coordinate (third column). They are produced by executing `map_generation.exe`, stored inside `GA_SIMULATOR/SOURCE` directory.

## 3. Compilation and Execution

This section presents the execution routine and file system management for archiving the output data generated during **simulation**. All subsequent commands must be executed from the `LSN_09/GA_SIMULATOR/SOURCE/` directory. The `GA_SIMULATOR` directory already includes two default random city distributions, so executing `map_generation.exe` is optional unless new maps are required.


### 3.1 Compilation

- Compile both source file (`GA.cpp` and `map_generation.cpp`):

```bash
make
```

- Remove residual files from previous executions:

```bash
make remove
```

- *OPTIONAL:* Remove all files and plot produced by previous executions and rebuild archive structure:

```bash
rm -r ../../circle
rm -r ../../square
mkdir -p ../../circle/plot
mkdir -p ../../square/plot
```

### 3.2 Input Parameters Initialization

- Open `../INPUT/input.dat` file and copy the following input parameters (choose `CIRCLE` or `SQUARE` as needed):

```
RND_ROW 0
N_PATH 1000
N_ELITE 100
N_CITY 34
CITY_DISTRIBUTION CIRCLE/SQUARE
N_GENERATIONS 150
P_SWAP 0.10
P_SHIFT 0.10
P_CROSSOVER 0.80
P_INVERSION 0.10

ENDINPUT
```

- Open `../INPUT/properties.dat` file and copy the following property parameters:

```
BEST_LOSS
MEAN_LOSS
BEST_PATH

ENDPROPERTIES
```

### 3.3 Execution (Map generation) *OPTIONAL*

- Execute the map generation executable:

```bash
./map_generation.exe
```

### 3.4 Execution (GA)

- Execute the GA simulation:

```bash

```
